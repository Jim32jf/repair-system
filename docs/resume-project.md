## 校园设备报修系统 | 后端开发 | 2026.10

**技术栈**：Spring Boot 2.7、MyBatis-Plus、MySQL 8、Redis、JWT、Knife4j、Hutool、Vue 3、Element Plus

**项目描述**：面向校园设备报修的工单管理系统，实现「学生报修 → 管理员派单 → 维修工处理 → 学生评价」完整闭环，支持学生、维修工、管理员三种角色的权限隔离。

**主要工作**：

1. 基于 Spring Boot + MyBatis-Plus 搭建分层架构，封装统一返回体、全局异常处理和参数校验，规范接口出入参。
2. 使用 JWT 实现无状态登录认证，自定义拦截器完成 token 校验；通过 `@RequireRole` 注解 + 拦截器实现基于角色的接口权限控制，方法级注解优先于类级。
3. 设计工单状态机（待派单 → 已派单 → 处理中 → 已完成 → 已评价），在 Service 层校验状态流转，拦截非法操作。
4. 使用 `@Transactional` 保证工单状态变更与流转日志写入的原子性，工单详情可追溯完整处理轨迹。
5. 基于 MyBatis-Plus 分页插件实现多条件分页查询，并按角色做数据隔离：学生仅能查询自己的工单，维修工仅能查询分配给自己的工单。
6. 使用 Redis 缓存分类列表（60 分钟过期），数据变更后主动删除缓存，并对 Redis 异常做降级处理，避免缓存故障影响主流程。
7. 使用 Vue 3 + Element Plus 实现管理页面，完成登录、报修、派单、处理、评价的全流程前后端联调。
8. 使用 Knife4j 生成在线接口文档，配合冒烟脚本完成接口回归。

**项目亮点**：

- 基于注解的轻量级 RBAC 权限控制，接口级越权校验
- 工单全生命周期状态机 + 操作留痕
- Redis 缓存 + 主动失效 + 故障降级
- 前后端一体，Vue 3 + Element Plus 管理页面可直接演示完整流程
- 统一异常处理与规范化的接口返回结构
- 分层清晰，DTO / VO 与实体分离，避免敏感字段（如密码）泄露给前端

## 面试讲解提纲（3 分钟版）

### 1. 背景（20 秒）

「学校设备报修之前靠微信群和纸质登记，容易漏单、也没法追踪处理进度。我做了这个系统，把报修、派单、维修、评价串成一个工单流程。」

### 2. 技术选型（20 秒）

「后端用 Spring Boot 2.7 + MyBatis-Plus + MySQL，登录用 JWT，接口文档用 Knife4j。选 MyBatis-Plus 是因为单表 CRUD 和分页能省很多模板代码。」

### 3. 我负责的部分（60 秒）

- 认证与权限：JWT + 拦截器 + `@RequireRole` 注解
- 工单状态机：5 个状态、4 个流转动作，Service 层校验
- 数据隔离：三种角色看到的数据范围不同
- 事务：状态变更 + 日志写入保持一致

### 4. 难点（60 秒）

挑一个讲，推荐这两个：

**难点一：越权问题**
「最早只做了登录校验，任何登录用户都能改别人的工单。后来在拦截器里加了角色注解校验，又在 Service 层加了归属校验——比如学生只能评价自己的工单，维修工只能操作派给自己的工单。两层校验，因为拦截器只能管接口级角色，管不了数据归属。」

**难点二：状态机**
「工单状态不能随便跳，比如没派单不能直接完成。我在 Service 层对每个动作校验前置状态，不满足就抛业务异常；状态变更和日志写入放在同一个事务里，避免状态改了但日志没写。」

### 5. 结果（20 秒）

「目前有 5 个业务模块、20 多个接口，完整的工单流程可以跑通，接口文档可以直接演示。」

## 常见追问 & 参考答案

**Q：JWT 和 Session 有什么区别？为什么选 JWT？**
A：Session 数据存在服务端，靠 Cookie 带 sessionId，多实例需要共享存储；JWT 是自包含的，服务端不存状态，适合水平扩展。缺点是 JWT 签发后无法主动失效，所以我预留了用 Redis 做黑名单的思路。

**Q：JWT 存在哪？怎么防止被盗用？**
A：前端一般存 localStorage 或内存，请求时放 Authorization 头。防盗用主要靠 HTTPS、设置较短过期时间，以及必要时用 Redis 黑名单主动踢下线。

**Q：拦截器里怎么拿到注解？**
A：`handler` 是 `HandlerMethod`，用 `getMethodAnnotation` 拿方法上的注解，拿不到再用 `getBeanType().getAnnotation` 拿类上的，实现方法级覆盖类级。

**Q：ThreadLocal 会不会内存泄漏？**
A：会，如果线程池复用线程而没清理。我在拦截器的 `afterCompletion` 里调用 `remove()`；拦截器提前返回 false 的分支也手动清理。

**Q：事务加在哪？为什么？**
A：加在 Service 的写方法上，`rollbackFor = Exception.class`。因为工单状态和流转日志必须一起成功或一起失败，否则会出现状态已变但日志缺失。

**Q：`@Transactional` 什么情况下会失效？**
A：同类内部方法自调用、方法非 public、异常被 catch 没抛出、抛的是受检异常但没配 rollbackFor、多数据源没配事务管理器。我项目里都是通过 Controller 调用 Service 的 public 方法，避免了自调用问题。

**Q：分页怎么实现的？**
A：MyBatis-Plus 的 `PaginationInnerInterceptor` 拦截 SQL 自动加 `LIMIT`，并查一次 `COUNT`。注意必须注册这个插件，否则分页不生效。

**Q：逻辑删除怎么做的？**
A：实体字段加 `@TableLogic`，全局配置 `logic-delete-field: deleted`，`deleteById` 会自动变成 `UPDATE ... SET deleted = 1`，查询自动带 `deleted = 0`。

**Q：密码为什么用 MD5？安全吗？**
A：这是教学项目的简化，MD5 不安全，容易被彩虹表撞库。生产应该用 BCrypt 或 Argon2 加盐，我了解这个改进方向。

**Q：如果工单量很大，分页查询怎么优化？**
A：先看慢查询日志和 `EXPLAIN`。常见做法是给 `student_id`、`repairer_id`、`status`、`create_time` 建联合索引，避免 `SELECT *`，深分页用游标（`WHERE id < lastId`）代替大 offset。

**Q：Redis 缓存怎么保证和数据库一致？**
A：项目里用的是「更新数据库后删除缓存」，下次查询回源重建，对分类这种低频变更数据足够。高并发场景可以加延迟双删，或者订阅 binlog 异步删缓存。

**Q：缓存穿透、击穿、雪崩怎么处理？**
A：穿透可以缓存空值或加布隆过滤器；击穿可以给热点 key 加互斥锁或逻辑过期；雪崩可以给过期时间加随机值、做多级缓存或限流降级。这个项目数据量小，主要做了 TTL 控制和 Redis 异常降级。
