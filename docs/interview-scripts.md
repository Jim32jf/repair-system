## 1. 项目介绍（30 秒）

**话术**：我做了一个校园设备报修系统，解决设备报修流程不透明的问题。技术栈是 Spring Boot + MyBatis-Plus + MySQL + Redis，前端 Vue 3。三种角色：学生报修、管理员派单、维修工处理，学生评价，完整闭环。我做得比较用心的是权限和状态机：权限做了接口级 + 数据级两层校验；状态机保证工单按五个状态顺序流转，非法操作被拦截。

## 2. 前端有校验，后端为什么还要？

**话术**：前端校验只能防误操作，防不了恶意调用。按钮能藏，接口藏不住，用 Postman 就能直接调。后端是最后一道防线。

**口诀**：前端防误操作，后端防恶意调用。

---

## 3. JWT 登录链路

**话术**：后端校验账号密码，通过后用密钥签发 JWT（payload 放 userId、username、roleCode 和过期时间），服务端不存任何东西。前端存 localStorage，axios 拦截器给每个请求加 Authorization 头。后端拦截器验签、验过期，通过就把用户放 ThreadLocal，afterCompletion 里清理（防内存泄漏）。

**追问-能放密码吗**：不能。payload 只是 Base64Url 编码不是加密，拿到就能解码看。签名防篡改、不防偷看。口诀：**编码不是加密，签名不是保密**。

**追问-token 被盗**：HTTPS 防传输偷听、短过期、payload 不放敏感信息；补救靠 Redis 黑名单主动作废，代价是破坏无状态、每次多一次查询。我项目没实现，是已知改进点。

---

## 4. 越权问题（项目难点·STAR）

**话术**：最初只有登录校验，测试发现学生能调接口看别人的工单。本质是接口权限管不了数据归属。我做两层：拦截器里用自定义 `@RequireRole` 注解 + JWT 里的 roleCode 做接口级校验；Service 层做归属校验——列表查询自动拼 `student_id = 当前用户`，详情和操作前验证工单归属，不符抛 403。测试脚本验证越权请求全部被拦。

---

## 5. 工单状态机（项目难点）

**话术**：工单 5 个状态按序流转，TINYINT 存库、常量类管理。每个动作在 Service 层校验前置状态，不满足抛业务异常——因为前端可以绕过，后端是最后一道防线。状态更新和流转日志在同一个 `@Transactional` 方法里，保证要么都成功要么都回滚，不然时间线和状态对不上。`rollbackFor = Exception.class` 是因为 Spring 默认只回滚运行时异常。不足：目前是"先查再改"，高并发有窗口，改进用 `UPDATE ... WHERE id=? AND status=?` 条件更新或 version 乐观锁。

---

## 6. Redis 缓存一致性（项目难点）

**话术**：分类列表读多写少，用旁路缓存：先读 Redis，未命中回源 MySQL 并以 JSON 写回，TTL 60 分钟；增删改后**删除**缓存而不是更新——并发下更新缓存可能写入旧值，删除能让下次读一定拿新值。所有 Redis 操作 try-catch，缓存故障降级直查库。极端并发有小的脏数据窗口，可用延迟双删或订阅 binlog，分类数据变更频率低加 TTL 兜底，评估后选了简单方案。

---

## 7. 缓存三兄弟

**话术**：都是缓存没挡住、请求砸到数据库。穿透：查**不存在**的数据，缓存永远不命中——解法缓存空值、布隆过滤器。击穿：**单个热点 key** 过期瞬间并发打库——解法互斥锁让一个线程重建、或逻辑过期异步刷新。雪崩：**大量 key 同时过期**或 Redis 宕机——解法 TTL 加随机、高可用、限流降级。

**口诀**：穿透查没有、击穿点一个、雪崩倒一片。

---

## 8. 索引 / B+ 树

**话术**：不建索引是全表扫描，一行行比对。索引是 B+ 树有序目录：非叶子节点只存 key 不存数据，分叉多、树很矮，千万级约 3 层、最多 3 次磁盘 IO；叶子有序并用链表相连，范围查询高效。代价是占空间、写要维护，所以只给高频查询列建。联合索引遵循最左前缀，像章→节→页，跳过章查不动。

**追问-低基数列**：status 只有 5 个值，选择性低，数据量大时索引价值小，甚至不如全表扫描。

---

## 9. 事务隔离级别

**话术**：隔离性解决多事务并发互相捣乱。三种捣乱：脏读=读到别人未提交的数据；不可重复读=同一事务两次读**同一行值变了**；幻读=两次读**多出新行**——一个"变"一个"多"。四级：读未提交、读已提交、可重复读、串行化，越严越慢。MySQL 默认可重复读：快照读靠 MVCC，当前读靠间隙锁防插入。

---

## 10. HashMap

**话术**：数组 + 链表 + 红黑树。put 先算 hash 高 16 位扰动，用 `hash & (len-1)` 定位（容量 2 的幂就是为了这个位运算）。位置空直接放；碰撞时 key 相同覆盖、不同挂链表尾。链表 ≥8 且数组 ≥64 树化，元素超容量×0.75 扩容两倍并 rehash。线程不安全，并发用 ConcurrentHashMap。1.7 头插法并发成环，1.8 改尾插 + 红黑树。

---

## 11. 线程池

**话术**：7 参数：核心线程数、最大线程数、空闲存活时间+单位、工作队列、线程工厂、拒绝策略。提交流程：**核心线程 → 队列 → 非核心线程 → 拒绝**（先入队再开人，反直觉必考）。默认拒绝策略 AbortPolicy 抛异常，还有丢弃、丢最老、提交者自跑。参数：CPU 密集 ≈ 核数+1，IO 密集 ≈ 2N 起步按压测调。

---

## 12. synchronized / Lock / volatile

**话术**：synchronized 是 JVM 关键字，自动加锁释放（异常也释放），只能死等。ReentrantLock 是 API，手动 lock/unlock 且必须在 finally（防异常不释放导致死锁），换来 tryLock 非阻塞、超时、可中断、读写锁。优先 synchronized，要高级功能才上 Lock。volatile 只保证可见性和禁止重排，**不保证原子性**——i++ 是读改写三步，两线程可同时读到同值各加一再都写回，丢一次；原子自增用 AtomicInteger 或锁。

---

## 13. IoC / AOP

**话术**：IoC 是思想（对象归容器造），DI 是手法（容器注入给我），解耦、可替换、好测试——我项目里构造注入拿 Mapper 就是。AOP 是横切逻辑抽出来代理织入——`@Transactional` 底层就是 AOP 动态代理套壳，所以同类自调用绕过代理事务失效。

---

**话术**：① 同类自调用——事务靠代理壳实现，`this` 是裸对象不走壳；② 方法非 public；③ 异常被 catch 吞了，壳收不到信号照常提交。我项目都从 Controller 外部调 Service public 方法，避开了。

# 第三轮补丁（2026-10-27 错题，优先背）

## 18. 事务 ≠ 幂等（今天最大的坑）

**口诀：事务 = 一件事不能做一半；幂等 = 同一件事不能做两遍。**

**话术**：连点三下提交会出三条工单——三个请求是三个独立事务，事务只保证单次操作内部完整（工单+日志同生共死），不防重复。防重复要靠幂等：方案一是页面加载时领一个一次性 token，提交时后端原子删除，删成功才放行；方案二是把"用户+设备+描述"算指纹 SETNX 进 Redis 设 5 秒短过期，抢不到 key 就是重复点击。前端按钮置灰只是体验兜底。

## 19. JVM 内存五块

**锚点：东西放仓库（堆），便利贴放工位（栈），规矩写手册（方法区）。**

| 块 | 存什么 | 共享/私有 |
|---|---|---|
| 堆 | **所有 new 的对象** | 共享 |
| 虚拟机栈 | 局部变量、方法调用（引用在这） | **私有** |
| 程序计数器 | 执行到第几行 | 私有 |
| 方法区/元空间 | 类信息、静态变量 | 共享 |

**衍生**：GC 主要在堆；StackOverflowError=递归太深栈爆；OutOfMemoryError=堆塞满。`SysUser user = new SysUser()` → user（遥控器）在栈，对象（电视机）在堆。

## 20. @RequireRole 标类 vs 标方法

**话术**：注解可标类也可标方法——标类上整个 Controller 所有接口把关（如 UserController 类上 ADMIN），标方法上只把单个接口把关（如 OrderController 里 page 不限、assign 要 ADMIN）。拦截器先读方法注解、没有再读类注解，**方法优先于类**。维修工调 /api/users/page 死在**拦截器 403**（角色不配进门）；维修工操作别人的工单死在 **Service 403**（数据不是他的）——两种 403，来源不同。

## 21. TCP 三次握手 / HTTP 状态码（我项目是活教材）

**话术**：三次握手是客户端发 SYN、服务器回 SYN+ACK、客户端再 ACK——三次是"双方各自确认能收能发"的最小次数，两次时服务器无法确认自己发的东西对方收得到。TCP 管送达（物流公路），HTTP 管内容（信的内容），HTTPS = HTTP + TLS，证书验身份、协商密钥加密、443 端口，上线第一件事是 HTTPS 防 token 被窃听。

**状态码背自己项目的**：200 成功；400 参数错（@Valid 拦截、密码错误）；**401 没带证件**（JWT 拦截器：token 空/假/过期）；**403 有证件没资格**（拦截器角色不对，或 Service 数据归属不对——两种 403）；404 资源不存在；500 服务器异常（全局兜底"系统繁忙"）；502 网关后端没响应（部署场景 nginx→应用挂了）。

**口诀**：401 问你是谁，403 问你能不能。

## 23. 网络 & OS 速记（R4 轮新增）

**TCP 可靠四件套**：序号（不乱）+ ACK 确认与超时重传（不丢）+ 滑动窗口（流量控制，不淹）——UDP 全不做，所以快但不可靠。口诀：**要可靠找 TCP，要快（丢包无所谓）找 UDP**。

**TIME_WAIT 等 2MSL**：怕自己最后的 ACK 丢了对方重发 FIN 时无人应答；顺带让旧连接残包死透，不污染新连接。

**输入网址全链路**：DNS 解析 IP → TCP 三次握手 → TLS 握手加密（注意拼写 **TLS** 不是 tsl）→ HTTP 请求（POST/GET 是它的方法）→ 状态码+HTML → 渲染。

**并发 vs 并行**：并发=单核交替演，并行=多核真同时。
**进程 vs 线程**：调度看线程，分家产（资源分配）看进程。
**死锁**：互持互等成环。预防两招：①所有线程按同一顺序加锁；②tryLock 带超时拿不到就放弃。

# 第四部分：中小厂+国企补缺卡（2026-10-27 新增，接续编号）

## 24. MQ：我项目为什么没用 + 一般用在哪

**话术**：我项目请求量小、处理都是同步完成的，没有异步需求，硬上 MQ 反而多出运维复杂度和丢消息风险——我不为堆技术而堆技术。MQ 三大经典用途：**异步**（下单后发通知、开发票拆成事件）、**削峰**（洪峰先入队，消费方按自己节奏拉，DB 不被打穿，本质是"空间换时间+排队"）、**解耦**（下游订阅事件，新增消费者不改上游）。我的项目若要加 MQ，最自然的场景是：工单完成后异步推通知短信，以及"已完成超过 24 小时未评价"的自动催评延时消息。

**追问-为什么削峰**：队列能囤，消费者按能力拉；请求直接打库则并发多大打多打。

---

## 25. MQ 不丢消息 / 重复消费 / 顺序

**话术**：按三段链路防：**生产者→broker→消费者**。生产者开 confirm（RabbitMQ publisher confirm / Kafka `acks=all`）确认 broker 落盘；broker 开持久化+副本同步；消费者**手动 ack，业务处理成功才确认**。代价：至少一次投递必然可能重复，所以**消费端必须幂等**（唯一索引/状态机/记 msgId）。顺序：Kafka 只保证单分区有序，全局有序代价大，实务按业务 key 哈希分区——同一工单的消息有序就够。

**口诀：发送要确认、落盘要副本、消费成功再 ack；接受至少一次，就用幂等收尾。**

---

## 26. 消息积压怎么办

**话术**：先定位是消费者变慢还是消费者挂了。三步：① 看死信/异常日志，有没有**毒消息**（一条反复失败卡住后面全部）——有就先把失败消息投死信队列，人工排查，别让一条堵一列；② 扩容：加消费者实例+加分区（Kafka 消费并行度受分区数限制，光加实例不加分区没用）；③ 极端积压来不及消化：临时新 topic+转发服务把消息打散再消费。预防线：积压量设监控告警。

## 27. 分布式锁（接第 5 张卡"先查再改"的坑）

**话术**：synchronized 只在单个 JVM 内有效，部署多实例就锁不住。Redis 基础版：`SET key uuid NX PX 30000`——原子抢锁、必须带过期防死锁、value 放请求唯一标识防误删；释放要"比对 value 再删"，比对+删除用 Lua 保证原子。遗留坑：业务没跑完锁先过期、主从异步复制锁丢失，生产级用 **Redisson**：`tryLock(waitTime, leaseTime)` + 看门狗自动续期（默认每 10 秒，持锁期间续到 30 秒）。但要说回来：我项目状态机那个"先查再改"窗口，单库场景用一条 `UPDATE ... WHERE id=? AND status=?` 判断影响行数就够了，**能用条件更新解决的不上分布式锁**——选最简单够用的方案也是设计能力。

**口诀：NX+过期+唯一值，Lua 比对再删；能用条件更新，不上分布式锁。**

## 28. GC 与 JVM 调优（第 19 张卡的追问）

**话术**：分代依据"对象大多朝生夕死"（分代假说）：年轻代 Eden+两块 Survivor，Minor GC 用**复制算法**快；Survivor 按比例晋升老年代，老年代对象存活久，Full GC 用**标记-整理**。收集器：CMS 并发标记清除、停顿短但有碎片；**G1** 把堆切 Region、可设停顿目标、JDK9+ 默认；ZGC 亚毫秒。Full GC 频繁的经典排查链：`jstat -gcutil` 看频率→ `jmap -histo`/dump 看谁占大头→ MAT 看支配者→ 回代码找（集合只加不删、静态缓存、ThreadLocal 没 clear）。

**追问-怎么判断内存泄漏**：Full GC 之后堆占用降不下去。

**口诀：Minor GC 复制靠分代，G1 能设停顿目标，泄漏看"GC 完还不降"。**

## 29. Spring Bean 生命周期 / Boot 自动配置

**话术**：Bean 一生：**实例化→属性填充→Aware 回调→`postProcessBefore`→初始化（init-method）→`postProcessAfter`（AOP 代理在这一步生成）→使用→销毁**。两个 postProcess 是 `BeanPostProcessor` 的插槽，Spring 的扩展性都从这条缝进来——@Autowired 注入、@Transactional 代理都挂在这。Boot 自动配置不是魔法：`@EnableAutoConfiguration` 读 `META-INF/spring.factories`/`AutoConfiguration.imports` 拿到候选配置类清单，每个类用 `@Conditional`（类存在吗、配置项有吗、Bean 缺吗）决定装配与否——**"约定优于配置"=预写好的配置+条件装配**。

**口诀：factories 提名，Conditional 决定入选，BPP 是 Bean 成长路上的服务区。**

## 30. MyBatis 一二级缓存 / `${}` vs `#{}`

**话术**：一级缓存 SqlSession 级，同会话同 SQL+参数直接命中，增删改或换 session 就清；二级缓存 namespace 级、跨会话共享，要开全局开关+实体实现 Serializable，且同 namespace 任何写操作**整个 namespace 清空**——粒度太粗、易脏，实务基本不开，缓存交给 Redis 显式做（我项目分类列表就是 Redis 缓存）。防注入：`#{}` 是 PreparedStatement 占位符，参数带引号进不去；`${}` 是字符串拼接，只在动态列名（order by）等必须时用，且**必须白名单校验**。

**口诀：`#{}` 是参数，`${}` 是拼接；用户输入永不进 `${}`。**

## 31. 幂等设计全集（第 18 张卡展开）

**话术**：按层次选方案：接口层重复提交=一次性 token；订单/支付=业务单号做**数据库唯一索引**（物理终极兜底，insert 冲突即重复）；系统内部=状态机条件更新 `WHERE status=?`，影响行数 0 就是没资格/已处理；MQ 消费=记录已消费 msgId 或靠业务唯一键。共同思想一句话：**把"做过没有"变成数据库能原子判断的事（唯一索引冲突、条件更新行数），而不是先读再判再写**。

**口诀：幂等终极依据 = 唯一索引 + 影响行数。**

## 32. 限流四件套 + 熔断三态

**话术**：固定窗口计数（简单，**临界问题**：两个窗口交界可放过 2 倍流量）、滑动窗口（细分格子，抹平临界）、**漏桶**（固定速率出水，强制平滑，适合整形）、**令牌桶**（先攒令牌、允许突发，用得最广，网关限流多为它）。单机 Guava RateLimiter；分布式 Redis+Lua 原子扣令牌；Java 生态直接上 **Sentinel**（QPS/线程数/参数限流，Warm-up 冷启动）。熔断三态：**Closed → Open（Trip）→ Half-Open 试探**。我项目体量不需要限流，但上线我会先给 `/api/auth/login` 加——按 IP+用户名限流、连续失败锁定，防暴力破解。

**口诀：漏桶求平滑，令牌桶容突发；熔断是跳闸，半开是合闸试电。**

## 33. 手写代码套路清单（蓝桥杯底子，别翻车在背不出）

**LRU**：HashMap + 双向链表，get/put 都 O(1)（访问的节点挪头、超容量删尾）；手写展示完，补一句"Java 里 `LinkedHashMap(accessOrder=true)` 覆写 `removeEldestEntry` 三行搞定，生产直接用"。**生产者消费者三种**：① synchronized+wait/notify（**while 防虚假唤醒**、notifyAll 防叫错人）；② ReentrantLock+两个 Condition（notFull/notEmpty 分开）；③ BlockingQueue 的 put/take（最稳，优先）。**单例五写**：饿汉、lazy+synchronized（性能差）、**DCL 必须 volatile**（new 是"分配内存→初始化→赋引用"三步，重排后别的线程拿到未初始化的半成品）、静态内部类（holder 懒加载，推荐）、枚举（防反射防序列化，最终 boss）。**Top-K**：大小 K 的小顶堆 O(N logK) vs 快速选择 O(N)。

**口诀：DCL 不 volatile = 拿到毛坯房；Holder 和枚举是单例双保险。**

## 34. 蓝桥杯怎么讲（三句话模板）

**话术**：「我大学参加过蓝桥杯（__组__奖/省赛），比赛最大的收获不是奖项，是**复杂度意识**——现在写代码我会先问这个数据量 O(n²) 扛不扛得住。日常后端最常用到哈希查找、双指针、堆的 Top-K，现场我可以手写 medium 题。」事实 + 可迁移能力 + 可验证承诺（敢当场写）。**结果不理想就不纠缠奖项等级，锚定"训练了思维方式"；千万别说"参加过，没拿奖，没什么好说的"。**
